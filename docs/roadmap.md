# 유니(youni) 상용화 로드맵

> 각 Phase의 "개발 산출물"은 product-spec.md의 스펙 ID를 가리킨다.

전제 (2026-07 확정):
- **팀**: 1인 운영 + Claude Code 개발
- **목표**: 3개월 내 첫 유료 매출
- **고객 순서**: 본인/지인 광고대행사 → 지역 광고대행사 → 소상공인 직접
- **예산**: 월 10~30만원 (인프라+운영)

원칙: 각 단계는 "출시 가능한 최소 단위"로 끝나고, 다음 단계 진입 전 종료 기준(Exit)을
통과해야 한다. 1인 운영이므로 동시에 여러 단계를 벌이지 않는다.

개발 기준선(2026-08-05): S00~S04와 S05 화성 dry-run **코드 준비**가 기본 브랜치에 병합됐다.
대시보드의 1회 리허설 예약, beta 지자체의 실 제출 차단, 최종 제출 직전 중단과 단계별 증적,
전용 완료 상태를 자동 검증한다. PR CI는 `corepack pnpm verify`와 로컬 Supabase 0002~0006 SQL
회귀 테스트를 실행하고, 수동 `workflow_dispatch`는 `verify`만 실행한다. 현재 기본 브랜치 구성은
PR #6에서 PR별 동시성 취소와 수동 실행을 유지한 채
중복 post-merge push 실행을 제거했다(별도 `main`은 동기화 전 기존 workflow 유지). Fly 워커 실가동과
본인 실계정·실사이트 리허설은 아직 통과하지 않았으므로 S05는 완료가 아니다.

## Phase 0 — 가동 준비 (지금 ~ 2주차)

**목표: 화성시 1곳에서 시스템이 실제로 돌아가는 상태.**

**현황 (2026-08-05)**: 0-1, 0-3~0-5와 S05 코드 준비 완료. Supabase는 `0001`~`0006` 순차
적용 보고와 `0006` 핵심 컬럼 3개를 확인했으며 스키마·함수 메타데이터 추가 확인은 남아 있다. 공개 Vercel
web(youni-web.vercel.app) HTTP 200도 확인했고, Upstash Redis 생성은 기존 운영 기록을 유지한다.
Fly 앱 `youni-worker`는 아직 release·IP 없이 `pending`이고 무료 체험 종료로 VM 조회·배포가
차단돼 있다. 따라서 **Fly 결제수단 등록·worker 배포, 본인 hsdr 계정
등록, 실사이트 dry-run 리허설은 여전히 남아 있다.** 2026-08-05 GitHub 배포 기록상 최신
Production은 `b393e06`이고 S01~S05가 들어간 기능 기준선 `65dc642`는 Preview까지만 성공했으므로,
Production 승격 여부와 환경변수도 먼저 확인해야 한다.

| # | 작업 | 상태 |
|---|---|---|

| 0-2 | 인프라 연결 — Supabase 마이그레이션/시드, Vercel(web), Upstash Redis, Fly worker | 🟡 최신 web Production·env 확인, Fly 결제수단·첫 배포 남음 (`SPEC-INFRA-01`) |
| 0-3 | 화성 hsdr.or.kr 실측 — 로그인 후 신청 플로우까지 셀렉터 확정 | ✅ (`SPEC-ADAPT-01`) |

| 0-7 | S05 코드 준비 — 대시보드 1회 리허설, beta 안전 게이트, 증적·전용 완료 상태 | 🟡 코드 준비 완료(PR #7), Fly·실계정 리허설 대기 |

로그인→폼 채움→시안 업로드까지 진행된 감사 스크린샷이 남아 있을 것. 2026년 8월 창구에서
증적을 남기지 못하면 S05를 미완료로 유지하고 리허설·실제 제출·결과 검증을 다음 열린 월초
창구로 순차 이월한다.

## Phase 1 — 본인 실사용 검증 (3주차 ~ 1개월)

**목표: 본인 대행사 업무를 유니로 대체. "내가 매달 쓰는 도구"가 되는 것.**

| # | 작업 | 세부 |
|---|---|---|
| 1-1 | S06 안전성 보완 → 실제 제출 1건 | 성공 precheck·원자적 claim·성공 판정·상태 CAS/보존을 구현·테스트한 뒤에만 `dry_run=false` 본인 신청 1건 → 접수번호 확인 |
| 1-2 | 이메일 알림 실연동 | Resend 1차 코드 완료 — API 키·발신 설정·실수신, dry-run 템플릿, `0007` 전달 메타데이터·backoff 보완 |
| 1-3 | 결과 크롤러 검증 | 인증 수집 1차 코드 완료 — 판정·기간·전체 계정 종료·fuzzy 알림 게이트 보완 후 실제 발표에서 검증 |
| 1-4 | 시안 검증 실전 튜닝 | 실제 반려 사례 기준으로 규칙·프롬프트 보정 |
| 1-5 | 운영 루틴 확립 | Sentry(무료) + 잡 실패 시 본인에게 알림, 주 1회 healthCheck 결과 확인 습관 |

**개발 산출물**: `SPEC-SUBMIT-02`(실제 제출 1건) · `SPEC-SUBMIT-03`(재시도 검증) ·
`SPEC-NOTIFY-01`(이메일 실연동) · `SPEC-RESULT-01`(uriad 인증 결과 수집) ·
`SPEC-AI-01`(시안 검증 튜닝) · `SPEC-INFRA-02`(Sentry·운영 루틴)

**Exit**: S05 통과 후 다음 열린 창구에서 **본인 신청 전 과정(자동 제출→결과 알림)이 무개입으로
완료**. 실패했다면 원인 수정 후 그다음 창구로 이월 — 이 검증 없이 Phase 2 진입 금지.

## Phase 2 — 첫 유료 고객 (1~3개월차) ★ 3개월 내 매출 목표 지점

**목표: 지인/지역 대행사 3~5곳 베타 → 그중 1곳 이상 유료 전환.**

| # | 작업 | 세부 |
|---|---|---|
| 2-1 | 온보딩 다듬기 | 가입→프로필→사이트계정→시안→자동신청 등록까지 막힘 없는 흐름, 한글 안내문 |
| 2-2 | 베타 모집 | 지인 대행사 + 화성 지역 현수막 제작업체에 직접 제안 (베타 무료 1~2개월) |
| 2-3 | 사업 기반 | 사업자등록(또는 기존 사업자 활용), 이용약관·개인정보처리방침 초안 — 특히 **사이트 계정 위임(암호화 저장·본인 계정 대리 입력) 동의 조항** 필수 |
| 2-4 | 수동 과금 시작 | 결제 모듈 전에 계좌이체 기반 월 이용료(예: 대행사당 월 3~5만원 또는 신청 건당 과금). 청구는 수동으로 — 결제 개발보다 가격 검증이 먼저 |
| 2-5 | 오산 어댑터 | 두 번째 지자체(osankoaa.or.kr) 구현으로 "지자체 추가 1주" 프로세스 검증 |
| 2-6 | 멀티테넌트 실전 검증 | 타인 테넌트 데이터 격리(RLS) 실사용 점검, 캡차 릴레이가 남의 손에서도 동작하는지 |

**예상 비용: 월 5~10만원** (Supabase Pro $25 전환 시점, worker VPS, Claude API 종량)

**개발 산출물**: `SPEC-WEB-01`(온보딩) · `SPEC-WEB-02`(제출 타임라인) ·
`SPEC-MAP-01~06`(게시대 위치 지도·지도 기반 신청) ·
`SPEC-BIZ-01`(약관·계정위임 동의) · `SPEC-BIZ-02`(수동 과금) · `SPEC-ADAPT-02`(오산 활성화)

**Exit**: **유료 결제 1건 발생** + 베타 고객의 신청이 본인 개입 없이 1창구 사이클 완료.

## Phase 3 — 상품화 (3~6개월차)

**목표: "아는 사람에게 파는 도구" → "모르는 사람이 결제하는 서비스".**

| # | 작업 | 세부 |
|---|---|---|
| 3-1 | 요금제 확정 | 베타 데이터 기반. 권장 구조: 대행사 플랜(월정액, 지자체 수·신청 수 상한) + 소상공인 플랜(건당) |
| 3-2 | 토스페이먼츠 연동 | 정기결제(빌링) + 통신판매업 신고 |
| 3-3 | 카카오 알림톡 | 솔라피 연동, 템플릿 사전 승인(2~4주 소요 — Phase 2 말에 신청 시작) |
| 3-4 | 지자체 확장 5~7곳 | 경기 남부 우선(수원 재조사·용인·평택·안산). 블로그 디렉토리 기반으로 접수처 확인 → 어댑터. uriad.com 등 공통 솔루션이면 공통 베이스 추출 |
| 3-5 | 랜딩 페이지 + SEO | "○○시 현수막 게시대 신청" 검색 유입용 지자체별 안내 페이지 (일정·수수료·규격 무료 공개 → 가입 유도) |
| 3-6 | 관리자 콘솔 | broken 어댑터 대응, 결과 매칭 확인 큐, 지자체별 성공률 대시보드 |
| 3-7 | 신뢰성 | 창구 기간 worker 이중화 또는 자동 재시작, 백업/복구 절차 |

**예상 비용: 월 15~30만원** (인프라 + 알림톡 건당 + 결제 수수료)

**개발 산출물**: `SPEC-BIZ-03`(토스 정기결제) · `SPEC-NOTIFY-02`(알림톡) ·
`SPEC-ADAPT-03`(경기남부 5~7곳) · `SPEC-WEB-03`(관리자 콘솔) · `SPEC-WEB-04`(랜딩·SEO) ·
`SPEC-RESULT-02`(매칭 확인 큐) · `SPEC-INFRA-03`(창구 신뢰성)

**Exit**: 유료 고객 10곳± / 월 신청 50건± / 신청 성공률 95%+ / 본인 개입 없는 창구 운영.

## Phase 4 — 확장 (6~12개월차)

**목표: 소상공인 셀프서브 + 데이터 기반 차별화.**

| # | 작업 | 세부 |
|---|---|---|
| 4-1 | 소상공인 셀프서브 | 회원가입만으로 끝나는 온보딩, 건당 결제, 모바일 웹 최적화 |
| 4-2 | 지자체 15곳+ | 수요(검색 유입·문의) 있는 곳 우선. 어댑터 추가를 반복 가능한 주간 프로세스로 |
| 4-3 | 시안 제작 연계 | AI 시안 검증 → 시안 자동 보정/생성 or 지역 제작업체 중개(수수료 모델) |
| 4-4 | 경쟁률 데이터 상품 | 축적된 결과 데이터로 게시대별 경쟁률·당첨 확률 제공 — 유료 플랜 차별화 |
| 4-5 | 수수료 납부 자동화 | 온라인 결제 지자체는 사용자 승인 게이트 뒤에서 결제 대행 |
| 4-6 | 필요 시 외주/채용 | 어댑터 유지보수·CS가 1인 한계를 넘는 시점의 첫 충원 판단 |

**개발 산출물**: `SPEC-ADAPT-04`(비uriad 템플릿 1호: newkoaa/수원 직영) 외 —
셀프서브·데이터 상품 스펙은 Phase 3 진입 후 product-spec.md에 추가 정의.

**Exit 지표(12개월)**: MRR 300만원±, 지자체 15+, 이탈률 월 5% 미만.
