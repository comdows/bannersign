## 1. 요약 (Executive Summary)

**youni(유니)** 는 지자체 현수막 게시대 신청을 자동화하는 멀티테넌트 SaaS다.
광고주·대행사가 사업자 정보와 시안을 **사전 등록**하면, 매월 지자체별 신청 창구(예:
화성시 1~5일)가 열릴 때 **자동으로 제출**하고, 추첨·선정 **결과를 수집해 알림**하며,
지자체별 규격에 대한 **AI 시안 적합성 검증**을 제공한다.

- **팀**: 1인 운영 + Claude Code 개발 (본인이 첫 고객인 광고대행사)
- **12개월 목표**: MRR 300만원±, 지자체 15곳+, 신청 성공률 95%+ ([로드맵 Phase 4 Exit](roadmap.md))
- **3개월 목표**: 첫 유료 매출 (지인/지역 대행사 유료 전환 1곳+)
- **현재 상태**: 화성시 전 플로우 실측·구현 완료, 인프라 배포 마무리 단계 — [기준선](product-spec.md#1-현재-빌드-상태-기준선-2026-07-26-실측)

## 2. 문제 정의

현수막 게시대는 저비용 지역 광고의 핵심 채널이지만, 신청 과정이 구조적으로 불편하다.

1. **창구가 짧고 제각각** — 지자체마다 접수처·기간이 다르고(화성 매월 1~5일 추첨 등),
   놓치면 한 달을 통째로 기다린다. 여러 지자체에 거는 대행사는 매월 같은 반복 작업을 한다.
2. **접수처가 파편화** — 지자체가 직접 운영하지 않고 장애인단체·광고협회·시설관리공단 등
   **수탁 기관에 위임**하며, 사이트도 제각각이다(uriad 계열 20곳+, newkoaa 계열, 직영 —
   [디렉토리](site-research.md)). 광고주는 지자체마다 계정을 만들고 사이트 구조를 익혀야 한다.
3. **규격 리스크** — 사이즈·색상·필수 문구 등 시안 규정이 지자체별로 달라, 어렵게 당첨되고도
   규격 위반으로 반려되면 게시 기회와 제작비를 날린다.
4. **결과 확인도 수동** — 추첨 결과가 개인 마이페이지에만 뜨는 곳이 많아 일일이 로그인해
   확인해야 한다.

**돈이 걸린 반복 작업 + 놓치면 되돌릴 수 없는 마감** — 자동화 SaaS가 잘 먹히는 조건이다.

## 3. 솔루션과 가치 제안

| 문제 | youni 기능 | 상태 |
|---|---|---|
| 창구 놓침·반복 신청 | 상시 주문 등록 → 창구 오픈 시 **완전 자동 제출** (단계별 감사 스크린샷) | 화성 구현 완료 |
| 접수처 파편화 | 지자체별 어댑터로 사이트 차이 흡수 — 사용자는 한 대시보드만 | uriad 팩토리로 20곳+ 확장 가능 |
| 규격 리스크 | **AI(Claude vision) 시안 검증** — 사이즈는 코드로, 문구·색상·금지 콘텐츠는 AI로 | 코드 완료, 실전 튜닝 예정 |
| 결과 확인 수동 | 결과 크롤링 → 선정/탈락 알림 | 부분 구현 |

**핵심 가치 제안: "신청 누락 방지 + 시간 절약."** 추첨 당첨을 보장하지 않으며, 이를
UI·약관에 명시한다(오해가 이탈·분쟁의 최대 리스크이므로 가치 축을 처음부터 명확히).

**포지셔닝**: 사용자가 **본인 계정으로 본인 신청을 자동화하는 대리 입력 도구.**
다계정·물량공세 기능은 정책적으로 금지(테넌트당 신청 unique 제약).

## 4. 시장

정밀 시장조사가 아닌 **실행 기준의 하향식 추정**이다(가정 명시).

- **지리적 확장 경로**: 경기 남부(화성→오산→시흥·안양·군포·의왕…) → 수도권 → 전국.
  실측 기준 uriad 동일 템플릿 접수처만 20곳+ — 어댑터 1개 재사용으로 커버 가능한 시장.
- **게시대 물량 감**: 화성시 1곳에만 게시대 197곳, 매월 추첨. 전국 지자체 226곳 중
  상시 게시대 운영 지자체 다수.
- **고객군 3층** (진입 순서):
  1. **본인/지인 광고대행사** — 검증·첫 매출 (Phase 1~2)
  2. **지역 광고대행사·현수막 제작업체** — 월 수십 건 신청하는 헤비 유저, 월정액 (Phase 2~3)
  3. **소상공인 직접** — 건당 결제 셀프서브, 롱테일 (Phase 4)
- **가정**: 지자체당 활성 광고 사업자 수십~수백. 대행사 1곳이 월 10~50건 신청.
  창구당 경쟁률은 결과 데이터 축적 후 실측치로 대체한다(Phase 4 데이터 상품의 원료).

## 6. 경쟁과 진입장벽

- **현재 대안**: ① 수동 신청(대부분) ② 대행 인력의 노동 ③ 지자체별 사이트 직접 이용.
  동일 컨셉의 자동화 SaaS는 확인되지 않음 — 시장이 작아 보여서 대기업이 들어올 유인이 낮고,
  1인 SaaS에는 충분한 크기.
- **진입장벽 (축적형)**:
  1. **어댑터 자산** — 지자체별 실측 셀렉터·플로우·예외 처리의 축적. uriad 템플릿 공통화로
     추가 비용 체감(1곳 1주 목표).
  2. **실측 노하우** — 수탁 구조(장애인단체·협회별 차이), 창구 규칙, 규격 문서 데이터베이스.
  3. **결과 데이터** — 게시대별 경쟁률·당첨 이력은 서비스 운영자만 축적 가능한 데이터.
- **관계 전략**: 수탁 기관에 트래픽 예절(rate limit) 준수, 규모화 시 공식 협력 전환 검토 —
  적대적 자동화보다 파트너십이 장기적으로 유리.

## 8. 운영·팀

- **1인 + Claude Code**: 어댑터 추가·유지보수를 AI 지원 개발로 회전. 본인이 도메인
  전문가(광고대행)이자 첫 사용자 — 피드백 루프가 가장 짧다.
- **운영 리듬**: 창구 기간(매월 1~5일)은 모니터링 전념, 그 외 기간에 기능 개발.
- **충원 판단**: 어댑터 유지보수·CS가 1인 한계를 넘는 시점(Phase 4)에 첫 외주/채용.

## 11. 마일스톤

실행 일정과 Exit 기준은 [로드맵](roadmap.md)이 단일 기준이다.

- **Phase 0 (지금~2주)**: 워커 배포 + 8월 창구 dry-run — *진행 중*
- **Phase 1 (~1개월)**: 본인 실사용 — 실제 제출·알림·결과 수집 무개입 완주
- **Phase 2 (~3개월)**: 베타 3~5곳 → **첫 유료 결제** ★
- **Phase 3 (3~6개월)**: 상품화 — 정기결제·알림톡·지자체 5~7곳·손익분기
- **Phase 4 (6~12개월)**: 셀프서브·15곳+·데이터 상품 — MRR 300만원±
